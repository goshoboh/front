# フロント台帳

PMS の帳票を日付別のスプレッドシートへ貼り付け、GAS 経由で表示・更新する静的 Web アプリです。

## ローカルでの起動

リポジトリのディレクトリで `python3 -m http.server 8000` を実行します。
パッケージのインストールやビルドは不要です。実データの利用には既存 GAS への接続とアプリ内認証が必要です。

## アプリを更新して公開する手順

1. コードを変更した後、リポジトリのディレクトリで実行します。

   ```sh
   python3 scripts/prepare-release.py
   python3 scripts/prepare-release.py --check
   ```

2. 生成された `index.html` と `version.json` を含め、アプリのファイル一式を同じ公開先へ反映します。公開後のファイルをさらに変更した場合は、コマンドを再実行します。
3. 公開先は同じ URL を維持してください。可能ならファイル一式を一括で切り替えます。順に転送する場合は `version.json` を最後に公開してください。
4. 起動中のアプリで更新通知が出たら、入力・保存を終え、「更新する」を押します。ホーム画面のアイコンを削除・追加する必要はありません。

版番号は配信対象ファイルの内容から自動生成します。同じ内容で再実行しても変わりません。
公開前の検証や CI では `--check` を使うと、版番号の更新忘れを検出できます。

## PWA の更新動作

- 起動時、画面に戻ったとき、オンライン復帰時、表示中は5分ごとに最新版を確認します。
- 新版があっても勝手に画面を再読み込みしません。入力画面が開いている間は「更新する」を押しても再読み込みしません。
- Service Worker は同じ公開先のアプリファイルをブラウザーの HTTP キャッシュから取得せず、ネットワークから取得します。GAS の通信・保存処理には介入しません。
- 認証キーの localStorage は更新時に削除しません。オフライン利用のためのキャッシュ機能はありません。
- HTTPS 配信が必要です（ローカル検証の localhost は例外）。配信元/CDN が古い内容を返す場合は更新できないため、`index.html`・`version.json`・`sw.js`・JS・CSS は `Cache-Control: no-cache` または `no-store` を推奨します。
- この仕組みを初めて導入する際は、既存の PWA をオンラインで開き直して新しいファイルを読み込ませます。iPadOS のホーム画面アイコン・アプリ名の変更は、画面や機能の更新とは別に OS 側の反映タイミングに依存します。

実データを書き換える操作は、公開確認のためだけに実行しないでください。

## 更新機能の検証

Playwright と Chromium が利用できる開発環境で実行します（アプリの動作には不要です）。

```sh
node tests/pwa-update.cjs
```

既存の Playwright や Chromium を使う場合は、`PLAYWRIGHT_MODULE` にモジュールのパス、`CHROMIUM_PATH` に実行ファイルのパスを指定できます。
テストは一時ディレクトリのコピーと架空データを使い、本番 GAS への通信や本番ファイルの変更は行いません。
版の生成、新版検知、編集中の再読み込み防止、キャッシュ回避、認証情報の保持、旧 Service Worker からの移行を確認します。
